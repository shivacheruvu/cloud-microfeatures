- **Databricks:** 14 scan events with a `VARIANT` payload, three broken the way a buggy writer breaks variant binaries
  (truncated value, unknown metadata version, undefined type byte). Extracting fields from the raw file fails with
  `MALFORMED_VARIANT`; `is_valid_variant` keeps 11 rows and quarantines E05, E09, E12; the clean per-lane report (22
  units, $67.48 over 3 lanes) equals the pure-Python reference. Finding: in local Spark 4.3, with the bad-header row
  present, even `WHERE is_valid_variant(payload)` in the same query as `variant_get` failed, so the check is a separate
  validate-and-write step. Second finding: Spark 4.3 shreds variants on Parquet write by default, so the test file is
  written with pyarrow as plain (metadata, value) binaries and read with an explicit `payload VARIANT` schema.
- **Google Cloud:** 9 stores, 9 two-way roads, one GQL query: `MATCH ANY SHORTEST` from each surplus store to each
  short store over 1-3 `Road` edges with `LET minutes = SUM(e.minutes)`: 7 pairs. Nearest-source plan routes 4 of 5
  short stores (25 cases, 91 drive minutes); the Airport store has no source within 3 hops. Must equal a DuckDB
  recursive CTE / plain-Python BFS; the road network is built so each fewest-hop path is unique.
