- **Databricks:** 3 stores x 28 days of oat-milk sales; one `psdf.groupby("store")[["price","units","promo"]].cov()`
  gives each store's 3x3 matrix. Raw slopes say 15.4 / 19.2 / 18.45 units per $1 cut, but in east and west price only
  moves on promo days (corr(price, promo) = -1.0), so those are really promo lift. North's mid-month price rise makes
  the two separable: the two-variable slope from the same matrix recovers **10 units per $1**. The local test runs the
  real pandas-on-Spark call on pyspark 4.3 (CI now installs `pandas<3` and `pyarrow`; pandas 3 breaks
  `pyspark.pandas`, which was the first CI failure on #108, fixed before merge).
- **Google Cloud:** a 120-row price book queried three ways over REST (JSON rows, `ARROW`, `ARROW` + ZSTD). Arrow
  batches are decoded with pyarrow and must equal the hand-parsed JSON rows exactly (Decimal prices, microsecond
  timestamps). Local build of the same payloads: 17,727 B JSON rows vs 10,824 B Arrow vs 4,112 B Arrow+ZSTD.
